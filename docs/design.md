# 든든전세 지도 주요 기능 설계

작성일: 2026-10-21. 이 문서는 기능 설계와 구현·검증 체크리스트를 함께 관리한다.

## 1. 목적과 기준 자료

LH 경기남부 든든전세 정정공고의 주택목록을 지도, 건물 목록, 세대별 비교 표, 홍보물 미리보기로 연결한다. 사용자는 세대별 조건으로 검색한 뒤 그 조건을 만족하는 건물의 위치와 자료를 확인한다.

- 공고 식별값: `2015122300020927`
- 공고명: `[정정공고][경기남부] 든든전세 매입임대주택 예비입주자 모집공고(비분양전환)`
- 공고일: 2026-09-30
- 기준 엑셀: `data/notices/lh_2015122300020927/공고첨부/69044664_(정정공고)(게시용)2026년경기남부든든전세매입임대주택주택목록(2026.09.30).xlsx`
- 원본 범위: 344세대, 원문 주소 문자열 56개, 주택군 38개, 원본 열 17개
- 첨부파일: 다운로드 62개. HWP/HWPX 제외. PDF·PPTX·이미지 미리보기 252페이지
- 이전 5월 공고의 다운로드 자료와 생성 데이터는 삭제했다. 수집·변환·검증 코드는 새 공고에 재사용한다.

보증금·면적·동호수·방수·층수·승강기·유형은 홍보물보다 정정 주택목록 엑셀을 우선한다. 원본의 불일치나 빈값을 추측해서 수정하지 않는다. 예를 들어 순번 10, 109, 229, 230의 실사용면적은 원본부터 비어 있어 `null`로 보존하고 화면에서 `—`로 표시한다. 전용면적이 있어도 실사용면적으로 대체하지 않는다.

## 2. 화면 구성

### 지도 탭

왼쪽에는 주 메뉴, 검색, 필터, 정렬, 건물 목록을 두고 가운데에는 지도를 표시한다. 건물을 선택하면 오른쪽에 상세정보를 연다. 좁은 화면에서는 목록과 상세정보를 겹치는 패널로 표시하고 목록/지도 전환 버튼을 제공한다.

네이버 지도의 탐색 흐름을 참고하되 LH 주택 비교에 필요한 동작으로 구성한다. Google 지도는 건물 상세의 외부 링크로 제공하고, 사용자 선택에 따라 기본 지도는 API 키가 필요 없는 OpenStreetMap으로 구성한다.

### 세대 표 탭

344개 원본 세대에서 현재 필터에 맞는 세대를 표시한다. 원본 17개 열마다 오름차순·내림차순 정렬을 지원한다. 건물 상세에서 열면 해당 건물 세대만 표시한다. 표 검색, 현재 표 CSV 내보내기, 원본 XLSX 다운로드를 제공한다.

### 저장 탭

건물 저장/해제를 지원한다. 저장한 ID는 브라우저 `localStorage`에 보관한다. 저장한 건물에도 검색과 필터를 적용한다. 서버 계정 간 동기화는 하지 않는다.

### 공고·자료

공고문 PDF, QnA PDF와 기준 XLSX를 모은다. PDF는 이미지 미리보기를 제공하고 XLSX는 원본 다운로드를 제공한다. LH 원문 링크를 함께 둔다.

## 3. 데이터 구조와 추적

`source-data.json`은 원본 세대 값, 원본 행 번호, A:Q 셀 값을 보존한다. `geocodes.json`은 원문 주소별 좌표, 조회문, 일치 주소와 출처를 보존한다. `data/datasets/2015122300020927/assets/attachments.json`은 파일 ID별 원본 경로와 이미지 페이지 경로를 관리한다.

`scripts/import_xlsx.py`와 `scripts/dataset.py`는 위 자료를 결합해 브라우저가 사용하는 `dist/data.js`를 생성한다.

- `meta`: 공고, 기준일, 전체 개수, 공통 첨부와 원본 열 정보
- `buildings[]`: ID, 주택군, 원문 주소, 지역, 검증한 좌표, 원본 세대 배열, 미디어 배열
- `units[]`: 순번, 시도, 시군구, 주택군, 주소, 동, 호, 공급형, 실사용면적, 확장면적, 전용면적, 방수, 층수, 승강기, 유형, 보증금, 비고
- `media[]`: 첨부 ID, 파일명, 원본 URL, 썸네일, 전체 페이지, 연결 구분과 자료에 표시된 주소

원문 주소 하나를 목록 항목 하나로 유지한다. 같은 도로명 주소의 A/B동이나 원문 주소 표기 차이는 원본 데이터를 합쳐 버리지 않는다. 같은 좌표의 항목은 지도에서 묶고, 클릭하면 개별 주소를 선택하게 한다. 좌표를 임의로 흩뜨리지 않는다.

## 4. 복수 선택 필터

### 필터 항목

| 항목 | 선택값 | 데이터 기준 |
|---|---|---|
| 지역 | 수원·시흥·안산·안양·여주·오산·용인·화성 등 자료의 지역 | 주소의 시 이름 |
| 보증금 | 1.5억 미만, 1.5~2억, 2~2.5억, 2.5~3억, 3억 이상 | 세대별 보증금(원) |
| 실사용면적 | 70㎡ 미만, 70~80㎡, 80㎡ 이상, 원본 미기재 | 세대별 실사용면적 |
| 방수 | 자료에서 추출한 방수 각각 | 원본 방수 |
| 주택유형 | 자료에서 추출한 유형 각각 | 원본 유형 |
| 승강기 | 있음, 없음 | 세대별 승강기 값 |

모든 항목은 체크박스 목록에서 복수 선택한다. 선택값이 없는 항목은 제한하지 않는다. 숫자 구간은 하한을 포함하고 상한을 제외한다. 예를 들어 2억은 `2~2.5억` 구간에 포함되며 `1.5~2억`에는 포함되지 않는다. 화면의 설명으로 경계를 명시한다.

### 결합 규칙

1. 한 항목 안에서 여러 값은 OR로 결합한다.
2. 서로 다른 항목은 AND로 결합한다.
3. 주택군·주소·동호수 검색, 저장한 건물, 현재 지도 영역 제한도 활성화되면 AND로 적용한다.
4. 세대별로 모든 조건을 평가한다. 건물 안의 서로 다른 세대가 각각 다른 조건을 만족하는 것을 하나의 일치로 합치지 않는다.
5. 조건에 맞는 세대가 1개 이상인 건물만 목록에 남긴다.
6. 지도는 그 목록과 동일한 건물 ID 집합만 표시한다. 결과가 없으면 지도 마커도 0개로 만든다.
7. 카드·지도 가격과 면적 범위, 세대수는 해당 건물 전체가 아닌 현재 조건에 맞는 세대로 계산한다.
8. 상세 세대 표와 전체 표도 같은 조건을 사용한다. 상세에는 필터 적용 여부를 표시한다.

예: 지역 `수원시 + 오산시`, 방수 `2개 + 3개`, 보증금 `1.5~2억`을 선택하면 두 지역 중 한 곳에 있으면서 방수가 2 또는 3이고 보증금이 해당 구간인 세대만 남는다.

### 필터 UI와 동기화

지도 위와 왼쪽 목록의 필터는 하나의 선택 상태를 공유한다. 어느 쪽에서 체크해도 양쪽 버튼의 요약과 체크박스가 함께 갱신된다. 버튼에는 첫 선택값 또는 선택 개수를 표시한다. 목록의 필터 버튼에는 적용한 항목 수를 표시한다.

필터 변경은 즉시 반영한다. 열린 필터 팝업은 다른 필터를 열거나 바깥을 클릭하거나 Escape를 누르면 닫힌다. 각 항목 초기화와 전체 초기화를 제공한다. 체크박스에는 명시적 레이블을 붙이고 키보드로 조작할 수 있어야 한다.

## 5. 목록·지도·정렬

목록 정렬 항목은 주택명, 주소, 최소 보증금, 최소 실사용면적, 방수, 일치 세대수, 홍보물 수, 유형, 승강기다. 오름차순·내림차순을 전환할 수 있다. 미기재 숫자는 0으로 바꾸지 않고 정렬 끝에 둔다.

각 목록 항목은 주택명, 원문 주소에서 읽기 쉽게 만든 주소, 보증금, 실사용면적, 방수, 승강기, 일치 세대수와 홍보물 수를 표시한다. 전체 주소는 상세에서 그대로 제공한다.

지도는 Leaflet과 MarkerCluster를 사용한다. 지도 마커에는 일치 세대의 최소 보증금을 표시한다. 겹친 마커는 클러스터로 묶으며 숫자는 주소 항목 수다. 같은 위치에 여러 주소가 있으면 주소 선택 팝업을 연다. 검색 결과 전체 보기, 확대/축소, 주소 라벨 전환, 현재 지도 영역만 보기 기능을 제공한다. 지도 저작자 표시를 유지한다.

## 6. 홍보물 연결과 웹 미리보기

연결은 같은 주택군 안에서만 수행한다.

1. `address`: 공백을 정리한 원문 주소가 일치함
2. `location`: 검증된 위치가 같음
3. `group`: 같은 주택군이지만 해당 건물 주소의 자료로 확정할 수 없음

상세에서는 위 순서로 자료를 표시하며 각각 `주소 일치`, `같은 위치 자료`, `주택군 공통`으로 표시한다. 주택군 공통 자료가 다른 건물을 포함할 수 있다는 설명을 제공한다. 홍보물이 없는 수원매탄에는 다른 건물 파일을 대신 연결하지 않는다.

PDF와 PPTX는 모든 페이지를 WebP로 변환한다. 미리보기 창에서 페이지를 세로로 탐색하고 확대/축소할 수 있다. 이미지 원본도 동일한 미리보기 흐름을 사용한다. 첫 페이지만 보여 주고 나머지를 누락하지 않는다. 각 파일의 원본 다운로드 링크를 보존한다.

## 7. 구현 파일과 실행

- `dist/index.html`: 화면 뼈대와 접근성 레이블
- `dist/style.css`: 데스크톱·모바일 레이아웃
- `dist/app.js`: 검색, 복수 선택 상태, 정렬, 목록/마커 갱신, 표와 미리보기
- `dist/data.js`: 원본과 미디어를 결합한 정적 데이터
- `dist/vendor/`: Leaflet 관련 라이브러리
- `dist/datasets/<noticeId>/<hash>/assets/`: 원본 파일, 미리보기와 썸네일

정적 HTTP 서버로 실행한다. `python -m http.server 8765 --bind 127.0.0.1 --directory dist`. 페이지 실행 중 별도 지오코딩 API를 호출하지 않는다. 지도 타일은 사용자가 현재 보는 영역만 불러온다. API 키나 인증 토큰을 소스에 넣지 않는다.

## 8. 검증 기준

- 원본 엑셀의 344개 순번과 모든 17개 열 값이 생성 데이터와 일치한다.
- 원문 주소 56개 전부 검증한 좌표를 가지고 있다.
- 다운로드 62개와 미리보기 252페이지의 모든 참조 경로가 존재한다.
- 각 필터에서 복수 선택 시 합집합이 적용되고, 항목 간에는 교집합이 적용된다.
- 필터 결과 건물 ID 집합과 지도 마커 ID 집합이 일치한다.
- 미일치 건물과 이전에 선택했던 상세는 결과에서 제거된다.
- 결과 0개이면 지도 마커도 0개다. 초기화 후 56주소·344세대로 복원된다.
- 미기재 면적은 `—`로 표시하며 면적 필터에서 명시적으로 다룬다.
- 원본 17개 항목의 표 정렬, 건물별 미디어 연결, 전체 페이지 미리보기, 모바일 화면 넘침을 확인한다.

## 10. 공고 데이터 교체 추상화

공고마다 화면 코드를 수정하는 방식 대신 버전 1.0.0의 표준 데이터 패키지를 입력으로 사용한다. 구조와 관계는 [DATA_STANDARD.md](DATA_STANDARD.md), 교체 명령·XLSX 열 매핑·실패 처리·되돌리기는 [DATA_GUIDE.md](DATA_GUIDE.md)에 명시한다.

- 데이터 원본: `data/datasets/<noticeId>/dataset.json`과 해당 패키지의 `assets/`
- 검증 계약: `data/schema/notice-dataset.schema.json`
- 공통 도구: `scripts/dataset.py`의 `validate`, `build`, `activate`, `import-current`
- XLSX 어댑터: `scripts/import_xlsx.py --config ... --output ...`
- 공고별 설정: `config/<name>.json`의 제목·출처·시트·헤더·열 매핑·필터 구간
- 활성 상태: `config/active-dataset.json`과 `config/validation-audit.json`
- 화면 입력: 검증 뒤 생성하는 `dist/data.js`. 화면 제목·지역·배지·기관명과 필터 구간도 데이터에서 읽는다.

## 12. 작업공간과 스킬 폴더 정리

## 14. 청약 경쟁률 백엔드·정렬·필터

LH 상세 공고(`selectWrtancInfo.do?panId=…`)의 공급정보 표 `htyListTb08`은 주택군 단위로 공급호수·모집인원·신청건수와 합계 행을 제공한다. 브라우저가 LH를 직접 조회하지 않고, 백엔드가 원문을 30분 주기로 파싱해 `/api/competition`으로 제공한다. 로컬 서버는 Python 표준 라이브러리 구현(`backend/server.py`, `backend/competition.py`, sqlite3)이고, 호스팅 Worker(`backend/site`, D1)는 같은 규칙의 `backend/competition.mjs`를 쓴다(16절).

- 파싱 결과는 응답 `panId`, 합계 행, 주택군 집합, 총 공급호수(주택목록 세대수)가 `competition-config.json`과 모두 일치할 때만 저장한다. 같은 주택군의 여러 행은 합산한다. 미공개 값은 null로 두며 0:1로 표시하지 않는다.
- 조회 실패 시 마지막 정상 수치·조회 시각을 유지하고 `stale-error`와 오류를 표시한다. 실패 후 자동 재조회는 5분 백오프한다.
- 로컬 서버는 30분 타이머로 갱신한다. Worker에는 타이머가 없으므로 `GET`이 30분 경과(또는 실패 후 5분 경과) 시 지연 갱신한다. `POST /api/competition/refresh`는 동일 출처만 허용하고 캐시를 무시한다. 동시 조회는 메모리 Promise와 DB 잠금(45초)으로 하나로 합친다.
- UI는 경쟁률 패널(상태·조회 시각·전체 신청건수·`지금 새로고침`), 공급호수/모집인원 기준 선택, 카드·상세·표의 주택군 경쟁률, `경쟁률순`·`신청건수순` 정렬(미공개는 항상 마지막), 경쟁률 구간 복수 선택 필터를 제공한다. 백엔드가 없으면 기존 지도 기능은 그대로 동작한다.
- 앱 원본은 `public/`, 호스팅 빌드 출력은 `dist/`(무시됨)로 분리했다. 스킬 템플릿은 `backend/`와 갱신된 `site/dist`를 포함하고, 실행별 `docs/RUN.md`에 백엔드 실행 명령을 기록한다.

## 16. Python 로컬 백엔드와 한 번에 실행하는 환경 스크립트

PATH에 Node.js가 없으면 `node backend/server.mjs`가 실행되지 않는다. Ubuntu 24.04의 apt로 받을 수 있는 Node(18.19)에는 `node:sqlite`도 없다. 그래서 로컬 서버를 Python 표준 라이브러리로 다시 구현하고 Node 로컬 서버는 제거했다. JS 파서(`competition.mjs`)는 호스팅 Worker용으로 남긴다. 두 파서는 같은 원문 픽스처에서 같은 JSON을 만들어야 하며, Node가 있으면 `tests/test_competition.py`가 둘을 대조한다. SQLite 스키마도 같아서 기존 캐시를 그대로 읽는다.

경쟁률 소스 URL은 사이트 단위다. 사이트 폴더마다 있는 `competition-config.json`의 `sourceUrl`을 쓰며, 이 값은 데이터셋 `notice.sourceUrl`에서 생성된다. `start_site.sh --list`와 서버 시작 메시지에 표시한다. 경쟁률 기능 이전에 만든 실행 폴더는 이 파일과 경쟁률 UI가 없어 "소스 URL 미등록"으로 표시하며, 경쟁률이 필요하면 새로 빌드한다.

- `scripts/project_env.sh`: 공통 설정. `.venv/` 전용 Python, `PIP_CACHE_DIR=tmp/pip-cache`, `PYTHONPYCACHEPREFIX=tmp/pycache`, `PYTHONNOUSERSITE=1`, UTF-8·TZ를 정한다. `python3-venv`가 없으면 `venv --without-pip`으로 만들고 시스템 pip(`--python`)로 venv 안에 pip를 설치한다.
- `./setup_env.sh`: 부족한 apt 패키지만 설치한다(실패해도 경고 후 계속). 이어서 `.venv` 생성·검사, requirements 설치, `pip check`, 도구 확인, 전체 테스트를 수행한다. `--no-system`, `--recreate`, `--no-test`를 지원한다.
- `./start_site.sh`: `public/`과 `--runs-dir`(기본 `lh-runs`)의 `*/site/dist`를 최신순으로 나열한다. 하나면 바로 실행하고, 여러 개면 대화형 번호 선택을 받는다. 터미널이 아니면 목록을 출력하고 종료 코드 2로 끝난다. 사용 중인 포트는 건너뛴다. 실행 폴더 사이트는 그 실행의 `backend/server.py`와 `tmp/competition/` 캐시를 쓴다.

## 17. 여러 공고 사이트 동시 운용

공고 URL로 빌드할 때마다 `lh-runs/<UTC시각>-<panId>-<고유값>/`이 새로 생긴다. 원본, 데이터셋, 미리보기, 지오코딩 캐시, 사이트, 경쟁률 캐시가 모두 그 안에 있어 실행끼리 상태를 공유하지 않는다. 기존 실행과 작업공간 `public/`은 덮어쓰지 않는다. 경쟁률 SQLite도 사이트별 파일이고 행은 공고 ID로 구분한다.

- `build_notice.py` 기본 `--runs-dir`을 cwd 기준 `lh-runs`에서 프로젝트 루트(`AGENTS.md`·`start_site.sh`가 있는 상위 폴더)의 `lh-runs/`로 바꿨다. `LH_RUNS_DIR`로 바꿀 수 있다. 다른 위치에서 실행해도 `start_site.sh`가 사이트를 찾는다. Codex SKILL.md의 `/workspace/lh-runs` 예시를 제거했다.
- `start_site.sh`에 `--all`(실행 중이 아닌 모든 사이트를 백그라운드로 실행, 빈 포트 순차 배정, 포트가 열릴 때까지 대기 후 URL 출력), `--bg`, `--stop-all`을 추가했다. 로그는 `tmp/logs/`에 남긴다.
- 빈 포트 검사에 `SO_REUSEADDR`를 적용했다. 서버를 내린 직후 TIME_WAIT 포트를 사용 중으로 오인해 재시작 주소가 바뀌던 문제를 고쳤다.

- [x] 표준 패키지로 같은 공고를 2회 빌드 → 별도 실행 폴더 2개 생성, 기존 폴더 불변
- [x] `--all`로 작업공간 + 실행 2개 동시 실행, 각 API `ok`, 사이트별 경쟁률 캐시 분리

## 18. 경쟁률 새로고침·기준 시각 표시와 지도 툴팁 폭

- 새로고침 버튼을 회색 텍스트 링크에서 아이콘이 있는 테두리 버튼(`경쟁률 새로고침`)으로 바꿨다. 조회 중에는 아이콘이 회전하고 비활성화된다. 위치는 사이드바 `청약 경쟁률` 패널 제목 오른쪽이다.
- 패널에 `데이터 기준` 줄을 따로 두었다. 마지막 정상 조회 시각(예: 10월 22일 (목) 00:12), 몇 분 전인지, 다음 자동 갱신 시각을 표시하고 1분마다 갱신한다. 조회에 실패하면 상태 줄에 "갱신 실패 · 위 시각의 이전 값 표시"로 알린다. 카드와 지도 툴팁의 경쟁률에도 짧은 기준 시각(`10. 22. 00:12 기준`)을 붙였다.
- 툴팁이 세로로 길쭉하던 원인: Leaflet 툴팁은 크기 0인 pane에 절대 위치로 붙는다. 그래서 `white-space:normal`이면 최소 내용 폭(단어 단위)으로 줄어든다. `width:max-content; max-width:min(340px,80vw)`로 고쳤다. 툴팁에 경쟁률·신청건수 줄을 추가했다.

## 19. 빌드 결과의 git 보관

공고 빌드(`lh-runs/<실행>/`)는 git에 커밋한다. 전달용 `reports/첨부파일.zip`은 `data/notices/lh_<ID>/`와 내용이 같아 재생성할 수 있으므로 `.gitignore`(`lh-runs/*/reports/*.zip`)로 제외한다. 실행별 `tmp/`(지오코딩 캐시·경쟁률 SQLite·임시 의존성)와 `__pycache__/`는 기존 규칙으로 제외된다. 가장 큰 파일은 약 8MB라서 GitHub의 파일 크기 제한(100MB)에 걸리지 않는다. git은 같은 내용을 한 번만 저장하므로 실행 폴더 안 `site/dist`와 `data/datasets`의 중복은 용량을 늘리지 않는다. 공고당 실제 증가분은 약 150~250MB로 예상한다.

## 20. clone 직후 실행 검증

git에 올라갈 파일만(`git ls-files -co --exclude-standard`) 새 폴더에 복사해 clone 직후 상태를 재현했다. `./setup_env.sh --no-system` → `./start_site.sh` 순서로 venv 생성, 패키지 설치, 테스트 통과, 사이트 200, 경쟁률 API `ok`, 화면의 카드 56개·기준 시각 표시를 확인했다.

- `--bg`/`--all` 서버를 `setsid`로 새 세션에서 띄운다. 실행한 터미널이나 도구 세션이 끝날 때 서버가 같이 종료되던 문제를 고쳤다.
- 변환 도구가 없는 상태의 테스트 실패는 `setup_env.sh`에서 경고로 처리한다(사이트 보기에는 불필요). 도구가 모두 있는데 실패하면 기존처럼 오류로 끝난다.
